## 图一 三层架构与独立模块

> 用途：专业软件架构总览图，依据已完成的横版动作闯关游戏架构说明。制作一张极清晰的横向宽幅三层架构图，技术文档风格，中文字大且准确。图中除了文件名，不出现任何英文逻辑名称。第一层“界面与交互层”，右上角文件名“KnightUI.exe”，五个并排小卡片：“输入采集”“场景绘制”“菜单交互”“状态显示”“音效反馈”。第二层“业务逻辑层”，右上角文件名“KnightGame.dll”；中央大卡片“游戏协调器”，它前面唯一入口卡片“统一入口”，周围五个独立职责卡片：“命令整理”“关卡流程”“交互处理”“存档协调”“快照生成”。界面层的所有连线只汇入“统一入口”，然后一根箭头通往“游戏协调器”。第三层“底层模块层”，七个完全分离的卡片，中文标题与唯一的英文文件名严格对应：“对象与状态 KnightState.dll”“地图与碰撞 KnightMap.dll”“运动与物理 KnightMotion.dll”“战斗与陷阱 KnightCombat.dll”“敌人决策 KnightAI.dll”“关卡与配置 KnightContent.dll”“存档与数据库 KnightSave.dll”。游戏协调器与七个底层卡片各有一条单独调用与结果返回线。七个底层卡片之间绝对不要画任何连线或箭头。底部一条独立注释“共享数据：命令｜只读快照｜状态变更单｜领域事件”。构图像严谨的软件系统蓝图，深海蓝背景、米白字体、青色调用线、少量琥珀色反馈线，不要游戏角色、装饰场景、额外文字、商标、水印。

最终文件：`architecture-overview.png`。

## 图二 单帧业务逻辑数据流

> 用途：中文软件架构文档中的业务逻辑流程信息图。横向宽幅、深蓝色实底、白色大字、青色箭头，简洁平整的专业蓝图，不要黑色空底、发光效果、噪点或模糊。标题“单帧业务逻辑数据流”。只画五个从左到右的宽大阶段卡片，文本准确、全部中文：第一卡“接收与校验”下方小字“输入命令、会话状态”；第二卡“生成行动意图”下方小字“玩家操作、敌人决策”；第三卡“运动与碰撞”下方小字“运动提案、地图裁决、运动收尾”；第四卡“伤害与交互”下方小字“攻击、陷阱、拾取、检查点”；第五卡“提交与呈现”下方小字“世界状态、关卡存档、画面快照”。五个卡片仅按顺序单向相连。每卡下面有一个分离的“调用模块”小条，第一卡写“业务层”，第二卡写“KnightAI.dll”，第三卡写“KnightMotion.dll / KnightMap.dll”，第四卡写“KnightCombat.dll”，第五卡写“KnightState.dll / KnightContent.dll / KnightSave.dll”；英文只允许出现在这些文件名内。最上方一条强调文字“所有底层调用由游戏协调器发起”；五个小条之间绝对没有连线或箭头。最下方独立的橙色回传条准确写“模块结果 → 状态变更单 → 领域事件与只读快照 → 界面呈现”。每个中文完整可读，不要任何额外文字、人物、商标或水印。
