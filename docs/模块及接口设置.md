# 模块接口协作约定

**项目：** Qt Knight  
**接口环境：** C++17、Qt 6.12、MSVC2022、64 位  
**依据：** [项目总体架构](游戏大体框架.md)、[业务逻辑与数据流](业务逻辑与数据流.md)

## 1 使用范围与调用边界

本文只定义目标接口、类型和调用规则，不记录开发进度。两人写代码时，先共同确认 `KnightContracts.h` 和各模块公开 `.h`，再分别编写 `.cpp`。函数栏只写 C++ 函数声明；开发状态另写文档。

调用方向固定为：`KnightUI.exe → KnightGame.dll → 七个底层 DLL`。界面只包含 `KnightGame.h`；业务层包含底层模块的公开头文件；底层模块之间**不包含对方头文件、不链接对方导入库、不直接调用对方函数**。下层返回共享值对象，业务层接收后再作为另一次调用的输入。

| 动态库 | 中文模块名 | 对业务层公开的头文件 | 私有数据 |
|---|---|---|---|
| `KnightGame.dll` | 游戏协调与业务 | `KnightGame.h`，只供界面包含 | `GameHandle`、会话、输入队列 |
| `KnightState.dll` | 对象与状态 | `KnightState.h` | `World`、实体注册表 |
| `KnightMap.dll` | 地图与碰撞 | `KnightMap.h` | `MapHandle`、空间索引 |
| `KnightMotion.dll` | 运动与物理 | `KnightMotion.h` | 只使用本次调用的临时变量 |
| `KnightCombat.dll` | 战斗与陷阱 | `KnightCombat.h` | 只使用本次调用的临时变量 |
| `KnightAI.dll` | 敌人决策 | `KnightAI.h` | 只使用本次调用的临时变量 |
| `KnightContent.dll` | 关卡与配置 | `KnightContent.h` | 文件解析缓存 |
| `KnightSave.dll` | 存档与数据库 | `KnightSave.h` | `SaveHandle`、数据库连接 |

`KnightContracts.h` 是上述目标共用的**类型头文件**，不对应一个 DLL。公开函数用本 DLL 的导出宏声明；“模块内部函数”只在本模块 `.cpp` 或私有头文件声明，不能由业务层调用。

## 2 先读懂函数签名、返回值与共享类型

### 2.1 `Result<CombatResult>` 到底是什么

以 `Result<CombatResult> evaluateAttacks(const CombatInput& input) noexcept` 为例：函数名是 `evaluateAttacks`；输入参数 `input` 的**类型**是 `CombatInput`；整个函数的**返回类型**是 `Result<CombatResult>`。`Result<T>` 是通用返回包装，包含调用是否成功的 `status` 和成功时的 `value`。这里把 `T` 换成 `CombatResult`，所以 `value` 的类型就是 `CombatResult`。`CombatResult` 再包含状态变更候选、伤害候选和事件候选。

以下是返回封装与战斗结果的关键代码节选，均放在 `src/contracts/KnightContracts.h`，并由使用它们的公开头文件包含。实际头文件要先定义 `ChangeBatch`、`DamageCandidate`、`EventBatch`，再定义 `CombatResult`：

```cpp
enum class StatusCode : std::uint8_t {
    Ok = 0, InvalidArgument, InvalidState, NotFound,
    InvalidFormat, VersionMismatch, IoFailure, OutOfMemory, InternalFailure
};

struct Status {
    StatusCode code = StatusCode::Ok;
    std::array<char, 256> messageUtf8{};
};

template<class T>
struct Result {
    Status status{};
    T value{};
};

struct CombatResult {
    ChangeBatch changes;
    std::vector<DamageCandidate> damage;
    EventBatch events;
};
```

调用方先检查 `result.status.code == StatusCode::Ok`，成功后才能使用 `result.value`。`messageUtf8` 以零字节结尾。若函数直接返回 `Status`，它只报告成功或失败，不另带数据值。若返回 `void`，本接口明确说明其释放等副作用。`const T&` 是本次调用只读输入；`T*` 是句柄或可空输入；可写 `T&` 则是输出参数或被修改的私有对象。公开函数的异常必须在所属 DLL 内处理，不能跨 DLL 抛出。

调用端读取结果的方式如下；这里的 `result.value` 是 `CombatResult` 结构体，`result.value.damage` 是 `std::vector<DamageCandidate>`：

```cpp
knight::Result<knight::CombatResult> result = knight::evaluateAttacks(input);
if (result.status.code == knight::StatusCode::Ok) {
    const knight::CombatResult& combat = result.value;
    const std::vector<knight::DamageCandidate>& hits = combat.damage;
    // 用 hits 继续组装本帧伤害候选。
} else {
    // 读取 result.status.messageUtf8；不要使用 result.value。
}
```

### 2.2 共享类型在哪里定义、每个结构体装什么

下表所有类型、别名和枚举统一声明在 `src/contracts/KnightContracts.h`。该头文件需要包含 `<array>`、`<cstdint>`、`<string>`、`<vector>`、`<unordered_map>`、`<variant>`。表中的“成员”是目标 C++ 字段类型和名称，不是模糊的业务说明。`std::vector<T>` 为值语义列表，`std::string` 存 UTF-8；两个开发者必须使用相同的 MSVC、运行时库、位数和构建配置。

| 类型 | C++ 成员或别名 | 含义及约束 |
|---|---|---|
| `EntityId`、`FrameId`、`CommandId` | 均为 `std::uint64_t` | 实体、逻辑帧、命令编号；零为无效实体或未分配命令 |
| `SlotId` | `std::int64_t` | 存档槽编号；零表示未选槽 |
| `LevelId`、`ResourceId`、`ContentRoot`、`DatabasePath` | 均为 `std::string` | 稳定关卡编号、资源编号、内容目录、数据库文件路径 |
| `Vec2` | `float x`、`float y` | 世界坐标或速度；横向右正，纵向下正 |
| `Rect` | `float x`、`float y`、`float width`、`float height` | 碰撞盒；实体碰撞盒的 x/y 相对实体位置，触发区的 x/y 为世界坐标；宽高大于零 |
| `Action` | `enum class`：`MoveLeft`、`MoveRight`、`Jump`、`Attack`、`Interact`、`Pause`、`Resume`、`NewGame`、`ContinueGame`、`Retry`、`SaveAndReturn`、`NextLevel`、`Exit` | 与具体键位无关的动作 |

| `EntityKind`、`AIState`、`AttackPhase` | `EntityKind`：`Player`、`Enemy`、`Pickup`；`AIState`：`None`、`Patrol`、`Alert`、`Chase`、`Attack`、`Return`；`AttackPhase`：`None`、`Windup`、`Active`、`Recovery` | 均为 `enum class`；使用方不得自行重新定义 |

| `EntitySnapshot` | `EntityId id`、`target`；`EntityKind kind`；`Vec2 position`、`velocity`；`Rect collider`；`int health`、`energy`、`remainingJumps`、`facing`；`bool active`、`grounded`；`FrameId invulnerableUntil`、`attackReadyFrame`；`std::uint64_t patrolPointIndex`；`AIState aiState`；`ResourceId prototypeId`、`spriteKey`、`equippedAttackId` | 从世界复制出的实体状态；敌人的目标、巡逻点与原型编号要供敌人决策读取；非角色的生命等字段为零 |
| `ProgressState` | `LevelId levelId`；`std::string checkpointId`；`int health`、`energy`；`std::vector<std::string> abilities`、`keyItems`、`permanentSwitches`、`clearedObjectives` | 跨关或跨会话的进度 |
| `WorldSnapshot` | `LevelId levelId`；`FrameId frame`；`std::vector<EntitySnapshot> entities`；`std::vector<AttackInstance> attacks`；`ProgressState progress`；`bool levelComplete` | 状态模块生成的完整只读世界副本 |
| `SaveData` | `std::uint32_t formatVersion`；`SlotId slotId`；`ProgressState progress` | 数据库存档值；不存敌人每帧坐标和攻击实例 |
| `SlotSeed` | `ProgressState initialProgress` | 新建槽位的初始进度 |
| `SlotSummary`、`SlotSummaryBatch` | 摘要：`SlotId slotId`、`LevelId levelId`、`std::string checkpointId`、`std::uint64_t updatedEpochSeconds`；批次：`std::vector<SlotSummary> slots` | 主菜单列出存档时使用 |

|---|---|---|
| `PlayerRules` | `float moveSpeed`、`jumpSpeed`、`gravity`、`maxFallSpeed`；`int maxJumps`、`maxHealth`、`maxEnergy`；`Rect collider`；`ResourceId spriteKey`、`defaultAttackId` | 玩家出生时的数值、碰撞盒和默认资源；当前血量等运行值不写回原型 |

| `CollisionItem`、`CollisionBatch` | 项：`EntityId entity`、`Vec2 allowedPosition`、`normal`、`bool grounded`、`hitCeiling`；批次：`FrameId frame`、`std::vector<CollisionItem> items` | 地图模块对运动提案的裁决 |
| `TriggerHit`、`TriggerBatch` | 命中：`EntityId entity`、`std::string triggerId`、`TriggerKind kind`；批次：`FrameId frame`、`std::vector<TriggerHit> items` | 裁决后站位所命中的危险区或交互区 |

| `DamageCandidate` | `EntityId source`、`target`；`std::uint64_t attackId`；`int amount`；`Vec2 knockback` | 尚未扣血的一条命中事实；陷阱伤害的 attackId 为零 |
| `CombatInput` | `WorldSnapshot before`；`CollisionBatch resolved`；`IntentBatch intents`；`LevelDefinition level` | 协调器组装的战斗输入；其中 resolved 是地图结果的副本 |
| `CombatResult` | `ChangeBatch changes`；`std::vector<DamageCandidate> damage`；`EventBatch events` | 战斗模块输出的候选结果；不是已提交的世界 |
| `AIResult` | `IntentBatch intents`；`ChangeBatch changes` | 敌人意图，以及 `AIState`、`Target`、`PatrolPointIndex` 等待提交的候选 |
| `CommitResult` | `WorldSnapshot world`；`EventBatch events` | 状态模块提交成功后的新世界与提交事件 |
| `RenderEntity`、`RenderSnapshot` | 可绘制实体：`EntityId id`、`Vec2 position`、`ResourceId spriteKey`、`int animationFrame`；画面：`FrameId frame`、`LevelId levelId`、`Rect view`、`std::vector<RenderEntity> entities`、`int playerHealth`、`playerEnergy`、`std::string messageKey` | 业务层输出给界面的绘制数据 |

**值匹配规则：** `ChangeKind::Position`、`Velocity` 使用 `Vec2`；`Facing`、`Health`、`Energy`、`JumpCount` 使用 `int`；`Active`、`Grounded`、`LevelComplete` 使用 `bool`；`EquippedAttack`、`Checkpoint`、`Inventory`、`Switch`、`Objective` 使用 `std::string`；`InvulnerableUntil`、`AttackReadyFrame`、`Target`、`PatrolPointIndex` 使用 `std::uint64_t`；`AttackInstance` 使用同名结构体；`AIState` 使用同名枚举。拾取物提交后通过 `Active=false` 停用。任何不匹配由 `applyChanges` 整批拒绝。

### 2.3 先确定数据结构放在哪个文件

接口不是把所有内容写进一个头文件。**跨 DLL 传递的值类型**放在 `src/contracts/KnightContracts.h`；**公开函数和不透明句柄的前向声明**放在各模块的公开 `.h`；**只有本模块实现能读写的结构体**放在该模块的私有 `.h`。私有头文件不安装、不加入供其他模块使用的公开包含目录，也不能出现在其他底层模块的 `#include` 中。下表是目标文件布局，不描述当前仓库完成程度。

| 数据或对象 | 定义文件 | 谁创建、谁使用 |
|---|---|---|
| `Vec2`、`Rect`、`LevelDefinition`、`TileLayer`、`EntitySnapshot`、`WorldSnapshot`、`SaveData` 等共享值类型 | `src/contracts/KnightContracts.h` | 内容、状态、地图、运动、战斗、敌人、存档和业务模块按需复制或只读；它们不是某个 DLL 的私有对象 |
| `GameHandle`、`InputState`、`SessionState` | `src/game/GamePrivate.h`；`KnightGame.h` 只写 `struct GameHandle;` | 业务 DLL 创建和修改；界面只持有 `GameHandle*`，不能读成员 |
| `EntityCore`、`CharacterRuntime`、`PlayerRuntime`、`EnemyRuntime`、`EntityRecord`、`World`、`WorldDraft` | `src/state/WorldPrivate.h`；`KnightState.h` 只写 `struct World;` | 状态 DLL 创建和修改；业务层只持有 `World*`，其余底层模块只收到快照 |
| `TileRef`、`MapHandle` | `src/map/MapPrivate.h`；`KnightMap.h` 只写 `struct MapHandle;` | 地图 DLL 创建索引并执行查询；业务层只持有 `MapHandle*` |
| `LevelDraft` | `src/content/ContentPrivate.h` | 内容 DLL 解析文件时暂存未验证数据；其他模块只能收到完整的 `LevelDefinition` |
| `SaveHandle` | `src/save/SavePrivate.h`；`KnightSave.h` 只写 `struct SaveHandle;` | 存档 DLL 拥有数据库连接；业务层只持有 `SaveHandle*` |
| `GameWindow`、`SceneRenderer` 等界面对象 | `src/ui/GameWindow.h`、`src/ui/SceneRenderer.h` | 界面程序使用；底层 DLL 不包含 Qt 图形类头文件 |

`KnightMotion.dll`、`KnightCombat.dll`、`KnightAI.dll` 不拥有跨帧可变对象：运动结果、战斗结果和敌人意图使用 `KnightContracts.h` 中的值类型，本次调用结束后模块不保留输入指针。这样敌人状态、攻击实例和玩家状态始终由 `World` 统一管理。

### 2.4 地图对象：静态定义与运行索引分开

项目中“地图”有两种含义。`LevelDefinition` 是**关卡文件解析后的静态数据**，由内容模块返回；`MapHandle` 是地图模块从静态数据建立的**运行时碰撞与触发区索引**。界面的场景对象只负责画出来，不是这两者之一。

在 `src/contracts/KnightContracts.h` 中定义公开的静态数据，下面展示地图相关结构体的成员；`Vec2`、`Rect`、枚举和原型类型按第 2.2 节先定义：

```cpp
namespace knight {
struct PlayerRules {
    float moveSpeed = 0, jumpSpeed = 0, gravity = 0, maxFallSpeed = 0;
    int maxJumps = 0, maxHealth = 0, maxEnergy = 0;
    Rect collider{};
    ResourceId spriteKey, defaultAttackId;
};

struct EnemyRules {
    float moveSpeed = 0, detectRadius = 0, attackRange = 0;
    FrameId attackCooldown = 0;
    int maxHealth = 0, maxEnergy = 0;
    Rect collider{};
    ResourceId spriteKey, attackId, behaviorId;
};

struct AttackRules {
    Rect hitBox{};
    int damage = 0;
    FrameId windupFrames = 0, activeFrames = 0;
    FrameId recoveryFrames = 0, cooldownFrames = 0;
};

struct TrapRules {
    int damage = 0;
    FrameId periodFrames = 0, activeFrames = 0;
};

struct PrototypeCatalog {
    PlayerRules player;
    std::unordered_map<ResourceId, EnemyRules> enemies;
    std::unordered_map<ResourceId, AttackRules> attacks;
    std::unordered_map<ResourceId, TrapRules> traps;
};

struct TileLayer {
    int width = 0;
    int height = 0;
    std::vector<int> tiles;  // 按行存储：tiles[row * width + column]
};

struct EntitySpawn {
    EntityId id = 0;
    EntityKind kind = EntityKind::Enemy;
    ResourceId prototypeId;
    ResourceId spriteKey;
    Vec2 position{};
    Rect collider{}; // 拾取物必须填写；敌人留空则使用原型碰撞盒
    std::vector<Vec2> patrolPoints; // 仅敌人可使用，坐标为世界坐标
};

struct TriggerDefinition {
    std::string id;          // 关卡内唯一的触发区编号
    TriggerKind kind = TriggerKind::Hazard;
    Rect area{};             // 世界坐标中的区域
    ResourceId prototypeId; // 陷阱、物品或机关的原型编号
    EntityId linkedEntity = 0; // 拾取区对应的物品实体；其他触发区为 0
};

struct LevelDefinition {
    std::uint32_t formatVersion = 1;
    LevelId id;
    LevelId nextLevelId;    // 最后一关可为空
    float tileSize = 0.0f;
    TileLayer collisionLayer;
    std::vector<TileLayer> visualLayers;
    Vec2 playerSpawn{};
    std::vector<EntitySpawn> spawns;
    std::vector<TriggerDefinition> triggers;
    std::vector<std::string> objectives;
    PrototypeCatalog prototypes;
};
}
```

碰撞层中 `0` 表示空格，`1` 表示实心图块，`2` 表示仅从上方落下时阻挡的单向平台；其他值由内容模块拒绝。`width × height` 必须等于 `tiles.size()`，所有图层尺寸一致，`tileSize > 0`。`visualLayers` 供业务层制作可见区域和界面绘制；`collisionLayer` 与 `triggers` 供地图模块查询。`spawns` 不重复放玩家：玩家只有 `playerSpawn` 一个出生点，玩家实体编号固定为 1；敌人和拾取物由 `spawns` 给出不小于 2 的唯一编号。玩家精灵取自 `PlayerRules.spriteKey`；敌人优先使用非空的 `EntitySpawn.spriteKey`，否则使用其 `EnemyRules.spriteKey`；拾取物必须填写自己的 `EntitySpawn.spriteKey` 和有效 `collider`。敌人的 `EntitySpawn.collider` 若宽高均为零则使用 `EnemyRules.collider`，否则两者都必须大于零并作为关卡实例的覆盖值。敌人出生项的 `prototypeId` 必须能在 `prototypes.enemies` 中找到，玩家和敌人的攻击编号必须能在 `prototypes.attacks` 中找到。

`TriggerDefinition.prototypeId` 对危险区引用 `prototypes.traps` 中的陷阱原型，对拾取区表示奖励物品编号，对门表示所需关键物品编号；检查点和出口可为空，其身份由触发区 `id` 和 `kind` 决定。拾取物的触发区 `linkedEntity` 必须指向同关的一个 `Pickup` 实体；拾取后该实体被设为不活动，业务层根据快照过滤对应触发区。非拾取触发区的 `linkedEntity` 必须为 0。关卡文件的路径和格式由内容模块处理，其他模块只接收 `LevelDefinition` 值对象。

在 `src/map/MapPrivate.h` 中定义运行时结构体；该文件包含 `KnightContracts.h`、`<cstddef>` 和 `<vector>`，只允许地图 DLL 的实现包含：

```cpp
namespace knight {
struct TileRef {
    int row = 0;
    int column = 0;
    Rect worldBounds{}; // 某个候选图块在世界中的矩形
};

struct MapHandle {
    LevelId levelId;
    float tileSize = 0.0f;
    TileLayer collisionLayer;
    std::vector<TriggerDefinition> triggers;
    // 下标仍是 row * width + column；元素是 triggers 中的索引。
    std::vector<std::vector<std::size_t>> triggerIndicesByCell;
};
}
```

`createMap(level)` 复制必需的碰撞层和触发区，建立 `triggerIndicesByCell`；`resolveMovement(map, before, proposed)` 用 `collisionLayer` 与 `TileRef` 裁决位移；`queryTriggers(map, before, resolved)` 先查附近格子的触发区索引，再返回 `TriggerBatch`。`MapHandle` 不保存玩家坐标，也不能修改 `World`。切关成功或加载失败时，由业务层调用 `destroyMap` 释放此句柄。

### 2.5 游戏角色：权威实体与只读快照分开

角色不是 Qt 的图形对象。玩家和敌人首先是**状态模块中的实体记录**；界面绘制的角色只是这些记录在某一帧的显示结果。玩家与敌人共享位置、速度、生命、碰撞盒等字段，同时各有自己的运行字段。

`src/state/WorldPrivate.h` 定义权威数据，可采用下面的组合结构；该头文件包含 `KnightContracts.h`、`<cstddef>`、`<optional>`、`<unordered_map>` 和 `<vector>`：

```cpp
namespace knight {
struct EntityCore {
    EntityId id = 0;
    EntityKind kind = EntityKind::Player;
    ResourceId prototypeId;       // 找到关卡原型参数
    Vec2 position{};
    Rect collider{};              // 相对角色位置的碰撞盒
    ResourceId spriteKey;         // 只提供资源键，不保存图像对象
    bool active = true;
};

struct CharacterRuntime {
    Vec2 velocity{};
    int facing = 1;               // -1 朝左，1 朝右
    int health = 0;
    int maxHealth = 0;
    int energy = 0;
    int maxEnergy = 0;
    bool grounded = false;
    FrameId invulnerableUntil = 0;
};

struct PlayerRuntime {
    int remainingJumps = 0;
    FrameId attackReadyFrame = 0;
    ResourceId equippedAttackId;
};

struct EnemyRuntime {
    AIState state = AIState::Patrol;
    EntityId target = 0;          // 0 表示当前没有目标
    std::uint64_t patrolPointIndex = 0;
    FrameId attackReadyFrame = 0;
};

struct EntityRecord {
    EntityCore core;
    std::optional<CharacterRuntime> character;
    std::optional<PlayerRuntime> player;
    std::optional<EnemyRuntime> enemy;
};

struct World {
    LevelId levelId;
    FrameId frame = 0;
    std::unordered_map<EntityId, EntityRecord> entities;
    std::vector<AttackInstance> attacks;
    ProgressState progress;
    bool levelComplete = false;
};

struct WorldDraft {
    World candidate;              // 验证全部变更成功后才替换权威 World
};
}
```

**实体约束：** `EntityKind::Player` 必须有 `character` 与 `player`、没有 `enemy`；`EntityKind::Enemy` 必须有 `character` 与 `enemy`、没有 `player`；`EntityKind::Pickup` 三项都没有。实体编号在同一世界内唯一。玩家的最大生命、最大能量、碰撞盒和默认攻击来自 `PrototypeCatalog.player`；敌人的对应值来自 `PrototypeCatalog.enemies[prototypeId]`，巡逻路线来自 `EntitySpawn.patrolPoints`。`CharacterRuntime` 保存原型确定的上限和随后变化的当前值；位置、冷却及决策状态都属于运行状态。拾取后把物品的 `core.active` 设为 `false`。已解锁能力、关键物品和永久机关属于 `World.progress`，不重复保存在角色字段里。攻击实例统一放在 `World.attacks`，避免一次挥击被错误地当成角色的永久属性。

`initializeWorld(level, restore)` 根据 `LevelDefinition.playerSpawn`、`spawns` 和可选存档，创建 `World` 内的玩家、敌人和拾取物。`applyChanges` 不直接改原 `World`：先复制为 `WorldDraft`，验证并应用整批变更，成功后一次替换；失败保留旧世界。`resetAtCheckpoint` 同样先构造候选世界，再整体替换。

状态模块通过 `readWorld` 和 `getPlayer` 把私有实体转换成 `EntitySnapshot`、`WorldSnapshot`。`EntitySnapshot` 在 `src/contracts/KnightContracts.h` 定义，是**只读传输结构体**：`id`、`kind`、`position`、`collider`、`active`、`prototypeId`、`spriteKey` 来自 `EntityCore`；速度和生命等字段来自 `CharacterRuntime`；玩家的 `remainingJumps`、`attackReadyFrame`、`equippedAttackId` 来自 `PlayerRuntime`；敌人的 `aiState`、`target`、`patrolPointIndex`、`attackReadyFrame` 来自 `EnemyRuntime`。运动、地图、战斗和敌人决策只能接收这些快照和关卡值对象，不能包含 `WorldPrivate.h` 或获取 `EntityRecord*`。

下面是快照和持久化进度的目标字段，定义在 `src/contracts/KnightContracts.h`。需要先定义 `AttackInstance`、`Vec2`、`Rect` 和各别名、枚举。这些结构体是一次调用的**值副本**，调用者可以读取，但修改副本不会改变 `World`；真正更新世界只能提交 `ChangeBatch`。

```cpp
namespace knight {
struct EntitySnapshot {
    EntityId id = 0, target = 0;
    EntityKind kind = EntityKind::Player;
    Vec2 position{}, velocity{};
    Rect collider{};
    int health = 0, energy = 0, remainingJumps = 0, facing = 1;
    bool active = true, grounded = false;
    FrameId invulnerableUntil = 0, attackReadyFrame = 0;
    std::uint64_t patrolPointIndex = 0;
    AIState aiState = AIState::None;
    ResourceId prototypeId, spriteKey, equippedAttackId;
};

struct ProgressState {
    LevelId levelId;
    std::string checkpointId;
    int health = 0, energy = 0;
    std::vector<std::string> abilities, keyItems;
    std::vector<std::string> permanentSwitches, clearedObjectives;
};

struct WorldSnapshot {
    LevelId levelId;
    FrameId frame = 0;
    std::vector<EntitySnapshot> entities;
    std::vector<AttackInstance> attacks;
    ProgressState progress;
    bool levelComplete = false;
};
}
```

`World.progress` 只保存跨关或需要恢复的进度，`EntityRecord.character` 才是当前逻辑帧的权威生命和能量。检查点、通关或主动保存时，业务层从**已提交**的玩家快照同步生命和能量到 `SaveData.progress`；加载存档时，状态模块把这两个值恢复到玩家角色。`EntitySnapshot` 中对非角色无意义的数字字段填零，`aiState` 填 `None`，无关的资源编号留空；读取前先检查 `kind` 和 `active`。敌人决策模块从快照读取上帧 `target` 与 `patrolPointIndex`，经 `AIResult.changes` 提交新值；战斗模块从 `prototypeId` 和 `equippedAttackId` 选择攻击规则。`WorldSnapshot.entities` 由 `readWorld` 生成，不能把快照当作可修改的角色对象。

### 2.6 其他模块自己的数据对象

| 模块 | 私有结构体及文件 | 必须保存的成员 | 创建、使用和销毁方式 |
|---|---|---|---|
| 游戏协调 | `GamePrivate.h` 中的 `InputState`、`GameHandle` | `InputState`：左右按住、跳跃/攻击/交互新按下标记、下一命令号；`GameHandle`：会话状态、命令队列、时间累积、当前 `World*`/`MapHandle*`/`SaveHandle*`、关卡定义、当前槽位、画面快照、事件队列 | `createGame` 创建；输入和每帧运行时修改；`destroyGame` 调用各模块销毁函数后释放 |

以下是这三类私有对象的目标字段。`GamePrivate.h` 仅由游戏协调 DLL 的实现包含；它可以包含各底层**公开**头文件来声明句柄，但不能包含底层私有头文件。`SessionState` 对应业务文档中的“主菜单、加载中、游玩中、已暂停、死亡中、关卡完成、退出”。

```cpp
// src/game/GamePrivate.h
namespace knight {
enum class SessionState {
    MainMenu, Loading, Playing, Paused, Dead, LevelComplete, Exiting
};

struct InputState {
    bool leftHeld = false, rightHeld = false;
    bool jumpHeld = false, attackHeld = false, interactHeld = false;
    bool jumpPressedThisFrame = false, attackPressedThisFrame = false;
    bool interactPressedThisFrame = false;
    CommandId nextCommandId = 1;
};

struct GameHandle {
    GameConfig config;
    SessionState session = SessionState::MainMenu;
    InputState input;
    std::deque<PlayerCommand> pendingCommands;
    std::uint64_t accumulatedMicroseconds = 0;
    std::optional<LevelDefinition> currentLevel;
    World* world = nullptr;
    MapHandle* map = nullptr;
    SaveHandle* save = nullptr;
    SlotId currentSlot = 0;
    RenderSnapshot rendered;
    EventBatch queuedEvents;
};
}
```

此头文件还需包含 `<cstdint>`、`<deque>`、`<optional>`。`leftHeld/rightHeld` 在按下与释放时改变，持续移动每帧读取；`jumpHeld/attackHeld/interactHeld` 用来识别新的物理按下，三个 `PressedThisFrame` 标记仅消费一次，避免按住移动时攻击事件被覆盖。`pendingCommands` 保存已编号、标明目标帧的命令；`currentLevel` 在主菜单时为空，进入关卡后才有值。`world`、`map`、`save` 只指向其他 DLL 创建的句柄，由业务层调用对应销毁函数，绝不直接 `delete`。

```cpp
// src/content/ContentPrivate.h
namespace knight {
struct LevelDraft {
    LevelDefinition partial;
    std::vector<ResourceId> unresolvedRefs;
    std::string sourcePathUtf8;
    int errorLine = 0, errorColumn = 0;
};
}

// src/save/SavePrivate.h；只在 KnightSave.dll 内包含 QtSql/QSqlDatabase。
namespace knight {
struct SaveHandle {
    DatabasePath path;
    std::string connectionName;
    QSqlDatabase connection;
    int schemaVersion = 0;
};
}
```

`LevelDraft` 只在 `loadLevel` 的解析、原型解析和验证过程中存在；`partial` 缺字段时不允许返回给业务层。`SaveHandle.connection` 的创建、事务、关闭和连接名释放都在存档 DLL 内完成，其他模块既不包含 `QSqlDatabase`，也不执行 SQL。

业务层持有 `World*`、`MapHandle*`、`SaveHandle*`，但这些都是**不透明句柄**：业务层可把句柄原样传回创建它的 DLL，不能读取其成员。`GameHandle` 的私有定义只供业务 DLL 使用，界面也遵守同样规则。

### 2.7 从文件到运行的一条具体数据路径

| 步骤 | 产生或持有的数据 | 结构体怎样使用 |
|---|---|---|
| 读取关卡 | 内容模块内部 `LevelDraft` → 公开 `LevelDefinition` | 校验图块、出生点、原型和触发区；半成品不交给其他模块 |
| 建立场景 | `LevelDefinition` → 地图模块的 `MapHandle`；同一份定义 → 状态模块的 `World` | 地图建立空间索引；状态建立玩家和敌人实体；两个模块不互相调用 |
| 推进一帧 | `World` → `WorldSnapshot` → 运动、地图、战斗和敌人决策结果 | 私有角色数据只由状态模块转换为快照；各算法模块返回候选 |
| 提交结果 | 业务层合并 `ChangeBatch` → 状态模块的 `WorldDraft` → `World` | 全部候选一次提交；失败不改变权威世界 |
| 绘制和存档 | 已提交 `WorldSnapshot` → `RenderSnapshot` 或 `SaveData` | 界面只绘图；数据库只保存可恢复进度 |

### 2.8 所有权、校验与编译边界

创建函数返回的句柄由**同一 DLL** 的销毁函数释放；业务层不能 `delete` 句柄。私有头文件只作为所属 DLL 目标的 `PRIVATE` 源文件使用；给其他模块的编译路径只提供公开 `.h` 和 `KnightContracts.h`。`const&` 输入在调用返回后不再被引用；需保留的数据由被调用模块复制。`Result<T>::value` 只在 `status.code == Ok` 时有效。

`ChangeBatch.sourceFrame` 必须等于当前 `WorldSnapshot.frame + 1`；一次逻辑帧由业务层合并候选，只调用一次 `applyChanges`，成功后世界帧号增加 1。存档只读取提交后的世界。数据库写入失败时旧存档不变。坐标必须有限，碰撞盒宽高必须大于零。若改变上述结构体的公开字段或类型，所有使用它们的目标必须用同一套工具链重新构建。

## 5 两人并行开发时如何对接

1. 先共同确定 `KnightContracts.h` 的结构体字段、枚举值、单位和契约版本，再确定第 3、4 节公开函数的签名。任何公开类型或签名变化，两人一起更新文档和头文件。
2. 一个模块的内部函数只由该模块实现文件使用；业务层只引用公开头文件。各底层 CMake 目标的链接项不得出现其他底层 DLL 的导入库。
3. 对方可以按表中的具体输入构造测试值，检查 `Status`，再检查 `Result<T>::value`。返回的快照、批次和关卡定义都是调用方持有的副本；不跨 DLL 传私有容器或私有对象指针。
4. 业务调用顺序见[业务逻辑与数据流](业务逻辑与数据流.md)。例如：`readWorld → decideEnemies → proposeMotion → resolveMovement → queryTriggers → finishMotion → evaluateAttacks/evaluateTraps → resolveDamage → applyChanges`，每一步的返回值都先回到业务层。
